# EdgeKappaKB：独立知识库实现与验证方案

状态：独立 KB、时间分桶学习、带权经验耗时分布、公共调用级组合与第四路 sidecar 输出已实现；在线反馈和快照接入已实现。四路 KB 独立输出预测结果，Linux 实际并发投递及配对效果验证尚未完成。

## 1. 目标与边界

目标：保留命令特征集合与包含关系，学习每条父子边的知识共享强度，减少不合适的回退，并帮助少样本节点利用相关历史。

已观察到的两类问题必须区分：

- 错误共享：例如测试命令匹配到主要记录短脚本、版本查询的 Python 节点。边权学习可能改善这类问题。
- 节点内部混杂：sqlglot 的部分 pytest 精确匹配已有几十条证据，仍严重低估长执行。若查询特征无法区分工作负载，调整 κ 不能解决其全部误差。

第一版不新增语义特征，不修复参数解析，不推断脚本内容，不把失败执行从时间目标中统一排除，不引入时间大小的偏序约束。所有边统一初始化，不随机初始化。新工具没有任何相关历史时返回不可用；从未执行过的新节点无法凭空学出可靠的父节点偏好。

新的 κ 是预测分布中的共享强度，与当前 `_SHRINKAGE_KAPPA=0.5` 的方差 shrinkage 含义不同，二者分开配置。名称建议为 `edge_kappa`。

## 2. 当前实现与需要改变的位置

- `services/sidecar/src/tool_time/_lattice_vendor/normalize.py`：repo 是可选特征，tool 和识别出的 target 是 core。第一版复用它的输出。
- `_lattice_vendor/features.py`：生成保留 core 的 bounded 子集节点以及完整节点。
- `_lattice_vendor/nodes.py`：原实现按“该次观测生成了哪些节点”聚合，不保证任意已有子集节点都收到该观测。当前默认按已有节点的集合包含关系重新聚合，并保留旧模式用于历史快照与消融对照。
- `tool_time/lattice_kb.py`：当前选择单个节点输出时间点估计；shrinkage 对完整特征精确匹配有捷径。新后端直接预测分布，不沿用此捷径。
- `LatticeTimeKB` 当前快照以原始 observations 重建统计，且 `fork_for_update()` 不复制衍生节点。边权是有顺序的学习状态，不能在每次重建时重置。
- `offline/runner.py`：已有按任务划分、冻结 KB 的评估流程。新增后端必须显式选择，不能把现有 runtime 指标误当作 Lattice 指标。

上述位置仅用于对照现有行为和复用外部适配能力，不是新 KB 的状态或算法依赖。第一阶段独立实现研究 KB，避免直接修改 vendored 算法以及资源预测逻辑。

新 KB 核心接收已经规范化的特征集合，不依赖 shell、mvdan 或旧 KB 类。第一版 shell 特征适配器复用并固定现有 normalize 的版本；以后更换特征提取器需要单独版本和实验。核心不承诺已支持非 shell 数据集，只有提供相同接口的合法特征与耗时标签后才可接入。

## 3. 节点、覆盖范围与边

### 3.1 节点集合

用训练集的命令特征生成与现有 bounded 规则一致的节点集合 V；只使用训练特征，禁止读取验证集标签或用验证集扩展训练图。节点 ID 使用排序后的特征列表的稳定哈希，不能使用 Python 的进程相关 hash。

构图可以提前使用全部训练命令特征；耗时计数和边权必须从空状态按训练事件回放学习。这是批量训练拓扑，不能把它宣称为严格在线的拓扑发现实验。

### 3.2 覆盖范围必须一致

对观测 i 的完整特征 F_i，定义：

    i 属于 S_v  当且仅当  F_v ⊆ F_i

每条观测对每个覆盖它的节点最多贡献一次。不能只给该观测自身生成的节点更新计数。

这是必要的数据一致性修正：它保证父节点样本包含子节点样本，才能安全计算差集。它也会改变当前 Python 根节点的统计，因此必须用独立基线测量收益，不能全归功于边级 κ。

通过特征倒排索引寻找已存在的子集节点；不为了满足覆盖定义生成所有可能子集。

### 3.3 边定义

父节点更一般：u → v 当且仅当 F_u 严格包含于 F_v，且 V 中没有中间节点 w 满足 F_u ⊂ F_w ⊂ F_v。即在保留节点集合上的覆盖边。

- tool 必须相同，禁止跨工具建边。
- 不要求仅差一个特征：bounded 图可能缺少中间层。
- target 仍按旧规则决定哪些节点被生成；但已有节点之间按特征包含建边，因此一个已有的 tool-only 节点可成为带 target 节点的祖先。
- 记录 `dropped_features = F_v - F_u`，用于解释共享的条件。
- 只连接最近父节点，避免同时把父、祖父都当成直接共享源。

这是一张稀疏包含 DAG；bounded 节点集合未必满足数学上格的所有封闭性质，论文中需准确表述。

### 3.4 新查询节点

查询完整签名不在训练图中时，创建临时节点 v，N_v=0；在训练节点中选它的最大严格子集作为父节点。冻结评估中该节点不写回 KB，边权使用统一初值。

在线扩展时允许把新完整签名持久化：保留旧节点间边，只增加指向新节点的边。该增量图可能保留不再是覆盖边的历史边；标记图版本，不能暗中重连或重新初始化旧边。图压缩留给显式重训练。

## 4. 父节点传递的是什么

对边 u → v，共享证据只使用差集：

    D_(u→v) = S_u \ S_v
    d_(u→v,b) = N_(u,b) - N_(v,b)

计数差必须非负，否则中止构建并报告覆盖统计不一致，不能静默截成零。

设 B 为桶数，ε=0.01 为固定平滑总质量：

    Q_(u→v)(b) = (d_(u→v,b) + ε/B) / (D_(u→v) + ε)

D=0 的边暂不参与预测与学习，不把平滑产生的分布当成真实证据。该边权状态仍保留，日后有外部证据时激活。

第一版 Q 使用父节点的原始差集统计，不使用父节点已经混合后的预测。这样不会递归借用子节点证据，更新梯度也是局部、明确的。

多个父节点差集可以重叠：各自内部观测不重复，但不同 Q 是相关的候选分布。预测采用凸混合；κ 是可学习的等效权重，不是相互独立的真实样本量。禁止据此宣称独立贝叶斯后验或用 N+Σκ 当真实有效样本量计算置信区间。报告父节点证据并集大小以及重叠比例。

## 5. 分桶预测

使用当前配置的时间桶边界，默认毫秒边界为 [100, 500, 2000, 10000]。不为每个桶另建 Lattice；每个节点持有 B 维计数。

令 A_v 为有外部证据的父边，a=0.01 为本节点平滑总质量：

    K_v = Σ_(e∈A_v) κ_e
    P_v(b) = [N_(v,b) + a/B + Σ_(e∈A_v) κ_e Q_e(b)] / [N_v + a + K_v]

- N_v=0 且 A_v 为空：返回 `no_edge_lattice_evidence`，不输出均匀分布冒充预测。
- N_v=0 且有父边：使用父分布混合，本节点平滑仅防止数值零概率。
- N_v>0 且无父边：使用自身平滑经验分布。
- 精确匹配也执行本公式，不再提前返回自身中位数。
- 预测桶是概率最大桶，同概率取较低桶；同时返回完整概率向量。

每条边一个 κ，整条边所有桶共享这个 κ。第一版不引入每桶 κ，避免参数膨胀和难以解释的桶间归一化问题。

## 6. 初始化与自动更新

### 6.1 初始化

每个子节点相同初始总强度 K0=1.0。有 m 条结构父边时，每条 κ_e=K0/m，包括尚无证据的边。预测时只计入活跃边；不因边激活或暂时失活而重分配旧权重。

K0 的值是待验证的工程起点，不是已调参结论，也不继承旧 κ=0.5 的实验结论。

### 6.2 损失与梯度

优化真实桶的负对数概率 ℓ=-log P_v(b*)。令 z_e=log κ_e：

    ∂ℓ/∂z_e = κ_e/(N_v+a+K_v) × [1 - Q_e(b*)/P_v(b*)]

这直接对应“哪个父节点比当前综合预测更支持真实结果”。使用执行前保存的 N、Q、P、κ 计算所有梯度，然后同时更新，不能逐条边更新并重新计算其他边的预测。

    g_e = clip(∂ℓ/∂z_e, -1, 1)
    z_e ← z_e - η g_e

第一版 η=0.1，固定学习率；不把这些常数当论文贡献。初始化统一，更新无随机性。

更新后将活跃 κ 投影到有下限和总上限的集合：κ_e≥10^-6/m，Σ_eκ_e≤100（使用明确的欧氏投影算法），再写回 z。m 为当前子节点结构入度。未活跃边本次不更新；重新激活后先检查总上限。记录触碰边界的频率；频繁触边表明上限或优化设置需要在训练内部验证。

不用持续拉回初始值的强正则，使错误的初始化能够被纠正。冻结评估中 κ 不更新。

### 6.3 更新哪些节点

训练回放时，对当前命令覆盖的每个已有节点 v，各计算一次执行前预测并保存 token。完成后每个节点各自更新入边一次，再统一增加节点计数。

同一事件可以为多个局部预测任务提供监督，但不能在同一个节点重复计数。它们不是独立实验样本，置信区间按 task 分组计算。

线上可采用同样的内部辅助预测，不要求对外返回每个节点的预测。限制节点数预算并报告跳过数量，不允许为了节省时间悄悄只训练精确节点、却声称所有边都可学习。

### 6.4 不能承诺的效果

- 没有子节点历史、只有一个父节点时，κ 对分布的作用仅剩平滑量级，不能学出有意义的共享总强度。
- 没有子节点历史但有不同父分布时，可以随第一次反馈学习父节点的相对可靠性，但预测该次执行时还没有这种反馈。
- 父分布完全相同时，无法辨识各自的独立 κ；只解释合计贡献，不强行给出父节点重要性排序。
- 没有语义参数共享时，首次出现的边无法继承其他边已学到的偏好。第一版解决可重复节点上的自适应共享，不承诺零样本语义迁移。

## 7. 因果性、事件与并发

顺序固定为：查询前提交已完成事件 → 保存执行前预测 token → 执行 → 完成事件到达 → 用 token 更新边权 → 增加计数。

沿用现有 `ts_end < ts_start` 可见性规则。相同时间不能看到对方结果；不能用完成时已经增长的计数重算原先的预测损失。

token 至少包含 call/clause ID、模型 generation、节点 ID、活跃边 ID、P、Q、预测时 κ 和归一化分母。只读重复预测不产生重复学习事件。完成事件以稳定 occurrence ID 去重，不能把内容相同的两次真实执行合并。

并发采用延迟反馈在线梯度：用启动时 token 算梯度，在完成事件正式提交时作用于当前边权。按完成时间和稳定事件 ID 排序；不得把旧 token 中的权重整体覆盖到当前模型。若缺少 token 或身份不匹配，完成方必须提供可信的原始 `FeatureQuery`，只更新合法观测计数，标记 `weight_update_skipped`，不能拿新预测伪造执行前预测。没有可核对的特征时拒绝该事件，避免计入错误节点。

历史训练按任务分组、固定种子确定任务顺序，任务内部按事件时间回放。不同任务的相对时间戳不可直接全局排序。该顺序是离线学习协议，不代表真实全局时间。另用多个固定任务排列检测顺序敏感性。

## 8. 标签、超时与复合命令

### 8.1 监督粒度

首个可验收实现以具有可信耗时标签的 clause 和单有效 clause 的 shell 调用为主。严禁把整条复合命令的耗时分配给每个 clause 来学习边权。

当前 `ClauseObservation` 没有完整的超时删失信息，研究适配器需保留 call/clause 关联、标签来源和 censor 状态；不能在转换时丢掉这些信息。

### 8.2 超时

- 完成执行：按精确桶更新。
- 已确认右删失且下界≥最高桶下界：桶确定是最高桶，可更新桶计数与 κ；不能把截断时间当精确持续时间。
- 右删失下界跨多个可能桶：第一版保留在数据集中并报告，不更新桶计数或 κ，也不纳入要求精确桶的主指标；单列删失预测质量。后续可扩展区间似然。
- 例如已确认的 600 秒超时在当前桶边界下属于最高桶，不能从分桶调参样本中排除。
- 失败退出仍是实际 wall-time 观测。管道掩盖失败、timeout 等检测使用统一标签审计，不能只凭 exit code=0 判定正常完成。

### 8.3 复合命令的第二阶段接入

先保持与原评估器完全相同的 shell 执行结构与管道规则，再替换 clause 的预测来源。不能将 `&&`、`||` 无条件当作所有分支都执行；动态执行结构继续按统一规则返回不可用。

仅有五个桶不能唯一决定串行求和后的分布，特别是最高桶没有有限上界。因此第一阶段不通过桶中点拼凑“精确”耗时，亦不宣称已重跑全部 952 条 sqlglot 预测。

第二阶段采用带权经验耗时分布：自身样本每条权重1，父差集样本每条权重κ_e/|D_e|，重复样本来自多个专家的权重相加，总贡献仍受Σκ限制。用该分布做确定性种子的抽样组合，串行求和、并行取最大；抽样数固定并单独检查蒙特卡洛误差。分桶学习中的微小平滑质量只用于损失，不伪造毫秒样本，记录组合分布与平滑桶概率的差异。

带删失的时间原子按区间传播，不能当作精确原子；组合结果跨桶时返回概率界/不确定质量到研究产物，不伪造归一化精确概率。完全确定部分用于严格配对指标，其余覆盖与不确定质量单列。若对外需要概率界，先扩展 JSON Schema。

连续 p50/p90 只在分布足以识别时输出；包含未识别删失尾部时允许不可用。复合命令组合与边权学习分开验收，防止组合假设掩盖学习效果。

## 9. 数据结构和持久化

新增独立包 `services/sidecar/src/edge_kappa_kb/`，核心只依赖标准库和本包，不导入 LatticeTimeKB、TrieKB 或 tool_resource。建议结构：

    edge_kappa_kb/
      __init__.py       # 导出 EdgeKappaKB 与公共类型
      types.py          # FeatureQuery、TimeOutcome、PredictionToken
      graph.py          # 有界节点集合、覆盖边、匹配索引
      statistics.py     # 节点计数、父差集、证据索引
      learner.py        # 分布预测、梯度、约束投影
      kb.py             # 生命周期、predict/observe/freeze/fork
      snapshot.py       # 独立版本、序列化与恢复

shell/旧 trace 适配器放在包外，例如 `tool_time/edge_kappa_adapter.py`；适配器提供 features、core_features、identity(tool)、标准时间单位、事件身份和标签来源。特征生成规则作为可替换配置传入，核心不调用旧 KB 的节点生成器。内部 bounded 生成实现需用对照测试确认第一版节点集合与既有规则一致。

建议拆成以下状态：

    NodeState:
      node_id, features, bucket_counts[B], observation_count, parents

    EdgeState:
      parent_id, child_id, dropped_features, log_kappa,
      update_count, last_update_id

    EdgeKappaState:
      graph_version, normalization_version, bucket_edges_ms,
      config, nodes, edges, generation, replay_cursor,
      pending_prediction_tokens, processed_event_ids

第一版研究实现保留 signature→observation IDs/桶计数索引，便于验证差集、计算证据并集和复现错误案例。统计充分稳定后再优化空间；不能先删除重复观测信息。

公共接口约定：

    EdgeKappaKB.fit(training_events, config) -> EdgeKappaKB
    kb.predict(query) -> BucketPrediction             # 纯只读，不创建学习事件
    kb.begin(query, event_id, start_time) -> (prediction, token_id)
    kb.complete(token_id, outcome) -> None            # 完成先缓冲，按可见性规则提交
    kb.commit_before(query_start_time) -> UpdateReport
    kb.freeze() -> None
    kb.fork_for_update() -> EdgeKappaKB
    kb.to_snapshot() -> dict
    EdgeKappaKB.from_snapshot(obj) -> EdgeKappaKB

`FeatureQuery` 包含完整特征、core特征、工具身份及特征版本；`TimeOutcome` 包含耗时或删失下界、start/end、task/call/clause ID、是否可信及标签来源。outcome不得提供模型预测时不可见的额外匹配特征。`BucketPrediction` 包含概率、预测桶、覆盖状态和证据说明，不强制拥有p50/p90。

`begin`先调用`commit_before`，再保存学习token；`predict`只查询当前已提交状态，不推进时钟、不更新计数。`complete`支持幂等重试，`commit_before`才提交梯度与计数。离线训练由fit的事件回放器驱动这些接口；冻结评估只调用predict。快照保存未提交事件，加载后不得让尚不可见标签提前进入统计。

派生 Q 不持久化，可用计数差重算。训练顺序、投影配置、边权和未完成 token 必须持久化。相同状态保存/加载后，下一次预测和更新应一致。

采用独立 `edge-kappa-kb.json` 与显式 schema version；新增 `contracts/edge-kappa-kb.schema.json`。不要给旧 v3 快照静默增加有状态算法并继续宣称完全兼容。旧 seed 可用于导入观测，但必须按明确回放顺序训练新后端；没有可靠顺序时标记重训练初始化，不声称恢复了旧学习轨迹。

后台 fork 必须复制边权、计数、事件去重状态和 pending token，发布时以 generation 原子切换。不能套用旧“只复制 observations，再重建所有衍生状态”的流程。

## 10. 实现与接入顺序

1. 新增独立包、类型、图/计数/分布模块和单元测试；旧 KB 仍是默认预测器，其节点覆盖统计单独修正，旧快照保留旧模式。
2. 新增 `offline/edge_kappa_eval.py`，复用数据加载和 split，独立输出逐条预测与边权解释。参数包括 split、seed、K0、η、是否学习、是否在线验证、输出目录。
3. 完成 clause 与单 clause shell 的冻结评估、在线评估及消融。
4. 完成经验分布组合和复合命令对照，再统计全量 call 指标。
5. 通过实验门槛后通过外部适配器接入 sidecar，sidecar独立持有`edge_kappa_kb`实例；不向`LATTICE_TIME_ALGORITHMS`添加枚举，不强迫结果满足旧`LatticeTimePrediction`点估计约束。
6. 如将结果暴露到公开协议，先更新相关 contracts Schema，再更新 Python/TypeScript 消费端。后端选择显式使用`edge_kappa`，与旧KB并列；独立seed文件和加载失败原因。默认仍保留旧算法，切换需有配对实验支持。

原则上不修改 `services/sidecar/src/tool_resource`；新增时间预测适配器可放在 `tool_time`。不修改 OpenClaw core 或只读 trace 数据集。

## 11. 验证实验与判定依据

### 11.1 必须有的消融

| 版本 | 目的 |
|---|---|
| 原 shrinkage κ=0.5 | 保留已知基线 |
| 原选择器 + 一致子集聚合 | 分离根节点统计修正的收益 |
| 新图 + 固定均匀边 κ | 分离分布混合/父差集设计的收益 |
| 新图 + 子节点单一可学习 K，父边等分 | 判断是否真的需要区分不同父节点 |
| 新图 + 可学习边 κ | 主方案 |

所有新图版本使用相同节点、父差集、标签、平滑和组合规则。第一版不混入解析修复、LLM 特征或人工工作负载规则。

### 11.2 数据协议

- 主实验复用现有每仓库按 task 的80%训练、20%验证清单；验证 KB 冻结，禁止利用验证标签调整 κ。
- 学习率、K0 等只在训练任务内部划分的小验证集上选择。给定初始值先跑，必要时做小规模预先声明的网格，不在最终验证集反复调参。
- 在线实验另起报告，从同一训练快照出发，先预测再更新。不能与冻结结果混写。
- 分别统计新签名、历史1–2条、3–10条、超过10条，以及精确节点、临时节点、跨repo共享节点。
- 单独列 sqlglot、其他仓库和总体；保持预测交集上的配对对比，同时报告覆盖率变化。
- 至少3个固定训练任务排列评估顺序敏感性，不把顺序当可挑选的超参数。

主学习目标是 log loss；主报告同时给 Brier、桶准确率、macro recall、跨≥2桶错误率、覆盖率，以及最坏案例。NLL 改善不保证 argmax 准确率改善，两者都需报告。

按 task 做配对 bootstrap 区间，不把同任务大量调用视为独立样本。连续时间指标只针对标签与预测都可识别的配对子集，单列排除原因。

验收不预设“必须提升若干百分比”。必须证明边级版本相对固定边和节点级版本有稳定收益，并展示高贡献边与被抑制边的实例；若修正聚合已解释全部收益，就如实否定边学习的增益。

### 11.3 解释产物

每条预测保存：task/repo/call/clause ID、原始命令、完整特征、实际桶、预测概率、节点样本数、每个父节点特征、差集样本数、κ、Q、混合占比、证据重叠率、更新前后κ、删失/失败状态、模型generation。

父边混合占比是 κ_e/(N_v+a+K_v)，比单独展示 κ 更易解释。它表示预测贡献，不代表因果重要性。

## 12. 必须通过的实现测试

- 集合覆盖正确；父计数逐桶不小于子计数；相同事件不重复计数。
- 多父节点差集、空差集、重叠差集均符合定义。
- 概率非负且归一化；全无证据返回不可用。
- 解析梯度与有限差分一致；有利父边增加、不利父边减少。
- 合成双父场景中能够选出更可靠父边；父分布相同不产生虚假的可辨识结论。
- 精确节点同样参与混合；历史增多时自身占比按公式增加（固定κ条件下）。
- 大入度初始化总强度不膨胀；边界投影保持约束。
- 用执行前token更新；延迟反馈、重复完成、乱序到达、相同时间严格可见性正确。
- 冻结评估不改变节点、计数或边权；临时查询节点不泄漏验证信息。
- 确定最高桶的超时保留，跨桶删失不伪造精确标签；复合调用不复制标签到所有子命令。
- 保存/恢复和后台fork后的后续预测、更新一致；修改桶边界/归一化版本需显式拒绝或重训练。
- 基线与新后端共享样本清单；每项指标能够由逐条预测重新计算。

本文件仅交付方案，没有运行新增算法、性能实验或尚未实现的测试命令。实现阶段遇到无法执行的验证命令，按仓库要求记录到 `docs/CURRENT_PLAN.md`。
